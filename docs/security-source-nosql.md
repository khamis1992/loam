The detector requires a MongoDB/Mongoose import or unshadowed require in the same file. It identifies body/query-shaped properties rooted in function parameters, follows local single-declaration aliases with no syntactic writes, and inspects object/array/spread filter construction. It recognizes filter positions in find/count/delete/update/aggregate/where/and/or methods, and the second argument of distinct. Update payloads are not mistaken for the filter. JSON.parse of request-shaped data, including route parameters, is considered capable of reintroducing object operators.

This is a syntactic review heuristic: it does not prove an Express request source or resolve the receiver's MongoDB/Mongoose type. Custom objects in a file importing those libraries can produce candidates. Imported models without a local library import, property mutations outside the limited construction pattern above, cross-function flows, arbitrary wrappers and schema validators are not modeled. Query casting, middleware sanitization, operator semantics and permissions need review. Returning no candidate does not certify those paths.

Explicit `$eq` wrappers, scalar conversion calls and static values do not match this operator-object rule; that is not a general security certification. A stable identifier under a positive `if (typeof value === "string")` (also number/boolean/bigint) is treated as scalar in that branch only. The else branch and uses after the if are not exempt. JSON.parse after a string check reintroduces the object risk. Arbitrary sanitizers are not validated by this detector.

Analysis is bounded to depth 32 and 2,048 expression visits per sink. Hitting a bound marks NoSQL coverage partial, gives a file-specific warning and makes the campaign partial. Unsupported languages and parse failures have separate counters. The source UI shows NoSQL counts beside SQL counts; parser completion means the configured rules ran, not full semantic coverage.
