# Loam — مراجعة التكامل والخدمات

تاريخ المراجعة: 2026-10-17. النتائج أدناه تميز بين استجابة الخدمة وبين إثبات تنفيذها الكامل.

## هوية التطبيق والتوافق

- صفحات الذاكرة والمهارات والتعلّم والشاشة والطرفية والرفقاء تحمل هوية Loam وتشارك ملف التصميم /loam.css.
- صفحة الرفقاء انتقلت إلى /companions.html، وأزيل زر تشغيل تطبيق خارجي لا ينتمي إلى Loam.
- عنوان نافذة سطح المكتب والقائمة وشريط النظام والمثبت أصبح Loam. المعرّف الجديد app.loam.desktop.
- النسخ المثبتة سابقاً تحتفظ بمجلد بياناتها القديم داخل AppData عند وجوده. هذا مقصود لمنع كسر المسارات المطلقة في الإعدادات ونقاط الاستئناف، ولا يغير الاسم الظاهر للتطبيق. النسخ الجديدة تستخدم Loam.
- جسر سطح المكتب الجديد window.loam؛ الاسم القديم متاح للتوافق مع صفحة مخبأة أثناء الترقية. متغيرات البيئة القديمة تقبل استمرار التشغيل، مع LOAM_PORT وLOAM_UPDATE_URL وLOAM_GITHUB_REPO للهوية الجديدة.
- الطرفية تتطلب معرف مهمة، وترسل هذا المعرف مع الإنشاء وكل عمليات الجلسة. فتح الطرفية دون مهمة يعرض إرشاداً ولا يبدأ جلسة عامة.
- مرفقات الرفيق تنشئ مسودة مهمة أولاً ثم ترفع داخل مساحتها؛ تغيير الرفيق أو بدء محادثة جديدة يمسح مرفقات الواجهة القديمة.
- عرض شاشة الجهاز لا يبدأ الاشتراك تلقائياً. يبدأ فقط بزر مشاركة الشاشة ويصف بوضوح أن الالتقاط على مستوى الجهاز، وليس عزلاً لسطح المكتب.

## ما يلزم قبل إعلان جميع الخدمات جاهزة للإنتاج

اختبارات الاستدلال الفعلي بالمزودين الآخرين، التقاط الشاشة بإجراء صريح، فتح جلسة PTY مع مهمة اختبار، تحقق بروتوكول جسر الوكلاء، وتجربة تثبيت وترقية Loam على ملف مستخدم سابق. لا تكفي استجابة كتالوج الأدوات لإثبات جميع هذه المسارات.

اختبار الواجهات الفرعية عبر node src/scripts/check-loam-ancillary.mjs نجح على Edge: منع تكرار النتيجة والاشتراك المزدوج، إرسال النمط ومعرف المهمة، رفع المرفقات في مسودة معزولة، مسحها عند بدء محادثة، عرض 320/768/1440 دون تجاوز أفقي، منع الاشتراك التلقائي في الشاشة، ومنع تشغيل طرفية دون مهمة. يستخدم خادماً وهمياً محلياً دون بيانات المستخدم.
