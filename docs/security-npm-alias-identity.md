# npm alias identity — revision 32

Inventory previously derived a package's identity solely from its installation path. For an npm alias such as `renamed-lodash`, OSV would receive the alias rather than the actual package name, potentially missing known advisories.

The analyzer now prefers the lock entry's explicit `name` and falls back to the installation name only when that field is absent. Invalid explicit names produce partial inventory coverage instead of silently falling back. Inventory retains `installedName` and `location`; the UI shows aliases alongside canonical name/version. OSV queries still contain only canonical package name, ecosystem and version. Multiple aliases of the same name/version collapse into one query while their installation records remain in inventory.

Evidence uses a real lockfile generated by npm 11.6.2 with `npm install --package-lock-only --ignore-scripts --no-audit --no-fund renamed-lodash@npm:lodash@4.17.20` in a dedicated fixture directory. No package code was installed or executed. The reusable lockfile is `src/scripts/fixtures/security-npm-alias-lock.json`. npm documents [alias installation](https://docs.npmjs.com/cli/v7/commands/npm-install/) and the [lockfile format](https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json/).

`check-security-dependency-alias.ts` verifies the npm-generated alias, scoped/nested aliases, canonical request payload, deduplication, malformed names and omission of installation paths from outbound queries. Its explicit `--live` mode queried only the fixed public lodash fixture and received five advisory IDs for lodash@4.17.20 on 2026-10-18. This confirms the identity path against the real provider, not runtime exploitability or remediation.

Source-server HTTP/UI integration passed with a visible canonical name and alias. Existing dependency coverage and pagination regressions passed. This change still trusts lockfile identity metadata: it does not verify installed archive contents, resolve all workspace/link provenance, or add ecosystems beyond npm.
