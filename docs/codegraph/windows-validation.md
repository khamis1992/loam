## Deviations from the spec (all documented in code comments)

1. **Lock-file hash** (`GRAPHIFY_PIN.lockFileSha256`): regenerated on this machine
   from the same frozen `uv.lock` at tag v0.9.95 (64 pins, mcp==1.29.0). Byte-identical
   to the box export after the 2-line autogenerated header, which embeds the `-o`
   output path (machine-specific). New pin: `9580d921…b6`.
2. **Start-up hook tripwire** (§6.3): on Windows the lock itself installs `pywin32`
   (marker `sys_platform == 'win32'`), whose `pywin32.pth` legitimately imports
   `pywin32_bootstrap`, and `uv venv` writes `_virtualenv.pth`. The box (Linux)
   observed neither. `findStartupHooks` now allows exactly these two provenance-verified
   names; every other `.pth` / `sitecustomize.py` still trips `broken`.
3. **git on the child PATH** (§A.2): the spec's child PATH assumed git in `/usr/bin`.
   On Windows git lives in Program Files, so graphify's export could not stamp
   `built_at_commit`. `CodeGraphService` now resolves git's directory once
   (`where`/`which`) and passes it as `gitDir`.
4. **`affected` exit code for missing symbols** (U-7): exit 0 with
   `No unique node match` text on Windows. Text classification takes precedence
   over an exit code that claims an answer; the prefix was added to the not-found
   set.
5. **Live-test git-cleanliness assertion**: the working copy legitimately holds
   uncommitted integration work, so the test snapshots `git status --porcelain`
   before the extract and asserts the after-snapshot is identical (the actual T6
   property: the scan adds nothing).

## OD-7 decision

W1–W12 all pass (W2 recorded, W8 deviation handled per the spec's own U-7 design
decision), so per the approved plan `DEFAULTS.codeGraph = { enabled: true }` is set
and the dist was rebuilt. Users can still turn it off with
`{ "codeGraph": { "enabled": false } }` in config.json.
