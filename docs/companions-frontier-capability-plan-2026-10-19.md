# مواصفات مساعدي Loam للوصول إلى مستوى Frontier — 19 أكتوبر 2026

## الهدف وحدود الحكم

يستطيع المستخدم إنشاء مساعد دائم، تكليفه بهدف، منحه خدمات وحسابات محددة، متابعة عمله وتوجيهه وإيقافه، واستلام نتائج صحيحة قابلة للتحرير. يستطيع المساعد استخدام خدمات Loam، والتحكم بجهاز المستخدم عند اختيار ذلك، أو العمل على جهاز مستقل خاص به عند الطلب. يستطيع عدة مساعدين التعاون دون اختلاط الملفات والحسابات أو تعطيل استخدام حاسوب المستخدم.

هذه وثيقة متطلبات وفجوات ومعايير قبول، وليست إعلانًا عن اكتمال التنفيذ. مصدر الحالة هو الفحص الحي في 19 أكتوبر 2026 الساعة 18:38 بتوقيت الرياض، ومراجعة الكود الحالية، ونتائج [التحقق الثالث](companions-fix-verification-round3-2026-10-19.md). لم تُعد جميع الاختبارات في جلسة إعداد هذه القائمة؛ أُعيد فحص API والمواضع المتعلقة بالفجوات. طلب المستخدم قائمة ومراجعة، ولم يبدأ تنفيذ هذه الخطة.

التفوق على جميع المساعدين في جميع الظروف لا يمكن إثباته بقائمة ميزات. المطلوب إثبات تقدم على منتجات وإصدارات محددة، وفي مهام محددة، بميزانيات وبيئات متكافئة، مع نشر حدود النتائج. الأهداف الرقمية أدناه مقترحات قبول للمنتج، وليست نتائج محققة أو معيارًا عالميًا رسميًا لـFrontier.

## المرجع التنافسي

للمقارنة المرجعية، اعتُبر Dot هنا **ChatGPT Dots**؛ توجد منتجات أخرى بهذا الاسم، ويجب تثبيت المنتج والإصدار عند إجراء المقارنة الفعلية. تصف وثائقه وكيلًا مستمرًا له حاسوب سحابي وذاكرة وتطبيقات متصلة وإمكان منح وصول اختياري للحاسوب المحلي. المصدر: [دليل Dots الرسمي](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot).

يصف Grok Bot حاسوبًا سحابيًا دائمًا، تشغيل تطبيقات، تولّيًا يدويًا، تعليمًا من عرض العمل، وروتينات وتواصلًا بين المساعدين. المصدر: [دليل Grok Bot الرسمي](https://x.ai/bot/guides/grok-bot-101). هذه أوصاف منشورة، وليست نتائج اختبارات مستقلة أجريت هنا.

فرصة تميز Loam المقترحة: تكامل عميق مع خدمات الإنتاج داخله، دعم عربي قوي، حسابات وأجهزة مستقلة فعلًا لكل مساعد، تحكم واضح للمستخدم، واستمرار موثوق مع نتائج قابلة للتحرير والتحقق. إثبات هذه المزايا شرط سابق لأي ادعاء تفوق.

## ثوابت المنتج

1. وجهة التنفيذ واضحة لكل مهمة واستدعاء: خدمات Loam، جهاز المستخدم، أو جهاز المساعد. لا تحويل صامت إلى جهاز المستخدم عند تعذر الجهاز المستقل.
2. المساعد لا يكتسب صلاحيات أكثر عند التفويض أو إضافة أدوات ديناميكية أو إعادة المحاولة.
3. نجاح المهمة يتطلب فحص الناتج أو الحالة النهائية، وليس رسالة نصية أو انتهاء استدعاء أداة فقط.
4. كل عملية حساسة تحترم قواعد المستخدم المسبقة؛ الأفعال الروتينية المصرح بها لا تطلب موافقة متكررة.
5. يجب أن يتوقف التنفيذ بعد إقرار الإلغاء؛ إذا تعذر إثبات توقفه، تظهر حالة غير مؤكدة بدل إعلان نجاح الإيقاف.
6. الهوية والملفات والذاكرة والحسابات لها مالك ونطاق وصول، ولا تنتقل بين المساعدين دون مشاركة صريحة.
7. كل خدمة مرئية للمستخدم لها رحلة مفهومة في الواجهة؛ الخدمات الخلفية لها حالة وسجل عند الحاجة.
8. تنفيذ خدمة Loam عبر API مصرح بها يختلف عن إعطاء المساعد shell عامًا على المضيف؛ تُفرض حدود المشروع والملفات على الخدمة نفسها.
9. الاستعادة والتحديث والترحيل لا تمحو الحالة السليمة قبل التحقق من البديل.
10. كل نتيجة مقارنة مرتبطة بإصدار وبيئة وميزانية ودليل، ويُفصل الاختبار المحاكى عن التشغيل الحقيقي.

## قائمة المواصفات الكاملة — 24 محورًا

الحالات تعني: **جزئي** = أساس موجود مع فجوات، **مطلوب** = لا يوجد تنفيذ كامل مثبت، **غير مقاس** = لا دليل جودة كافٍ. P0 لإغلاق صحة التنفيذ؛ P1 للاستخدام الإنتاجي الأساسي؛ P2 للتوسع والجودة؛ P3 لإثبات التفوق.

### C01 — هوية دائمة كاملة لكل مساعد — جزئي، P1

- اسم وصورة وصوت وتخصص وتعليمات وإعداد نموذج مستقلة، بإصدارات وتاريخ تغييرات.
- قوالب قابلة للإنشاء والمعاينة والنسخ مع تحديد ما يُنسخ من ذاكرة وحسابات وملفات.
- أرشفة واستعادة وحذف منفصلة، مع تعطيل جميع المشغلات عند الأرشفة.
- حزمة تصدير/استيراد بإصدار مخطط وملفات مرفقة وعلاقات سليمة وبيانات تاريخية محفوظة؛ لا تصدير أسرار خام افتراضيًا.
- إدارة هذه العمليات من الواجهة، مع فحص الحزمة قبل اعتماد الاستيراد.
- **القبول:** مساعد له إعدادات وروتينات وذاكرة وصوت وملفات ينجح في دورة تصدير→استيراد→أرشفة→استعادة دون فقد غير معلن أو تفعيل روتين معطل.

### C02 — أوضاع عمل حقيقية ومستويات استقلال — جزئي، P1

- تثبيت دلالات المحادثة، خدمات Loam، جهاز المستخدم، الجهاز المستقل، الفريق، والعمل المستمر.
- عرض مكان التنفيذ والحساب المستخدم والصلاحيات الفعلية لكل مهمة.
- مستويات استقلال: اقتراح، تجهيز للمراجعة، تنفيذ مصرح، متابعة مستمرة ضمن قواعد محددة.
- تغيير الوضع لا ينقل ملفات أو حسابات أو عمليات جارية ضمنيًا؛ يظهر أثر التغيير قبل التنفيذ.
- منع تجاوز الوضع من خلال أداة فرعية أو تفويض أو إعادة تشغيل.
- **القبول:** مصفوفة أدوات × أوضاع × منح × تعطيل تُختبر في الخادم والواجهة، وتؤكد رفض المسارات المخالفة.

### C03 — جهاز مستقل لكل مساعد عند الطلب — جزئي، P1

- إنشاء جهاز مرتبط بالمساعد أو إسناد جهاز مملوك له، مع قرص وعمليات وهوية نظام مستقلين.
- جهاز دائم للمهام المستمرة، أو مؤقت لمهمة واحدة، مع سياسة واضحة للاحتفاظ بالنتائج.
- تثبيت الأدوات والبرامج اللازمة داخل الجهاز نفسه.
- ملفات ومتصفح وحسابات منفصلة، مع جسور نقل صريحة إلى خدمات Loam.
- لا مشاركة جهاز أو جلسة بين المساعدين إلا باختيار واضح مع أقفال وسياسة وصول.
- **القبول:** مساعدان يعملان في الوقت نفسه على المسار نفسه داخل جهازين ولا يرى أحدهما بيانات الآخر؛ المستخدم يواصل استخدام حاسوبه.

### C04 — مزودو الأجهزة والتزويد والموارد — جزئي، P1/P2

- Linux محلي، Windows VM، جهاز بعيد موجود، وسحابة مُدارة بعقود موحدة وقدرات معلنة.
- SSH وسيلة اتصال؛ دليل داخل حساب بعيد لا يُصنف جهازًا معزولًا مستقلًا دون حدود نظام تشغيل مناسبة.
- قوالب بحث وبرمجة وأوفيس ومونتاج، بإصدارات قابلة للتثبيت والتحقق.
- CPU/RAM/disk/GPU وشبكة بحصص مفروضة، وقياس استخدام وتكلفة وإيقاف خمول.
- فحص جاهزية التطبيق والأدوات والأذونات والشاشة، ومعالجة فشل التزويد وتنظيف الموارد الجزئية.
- **القبول:** إنشاء نظيف من الواجهة لكل مزود معلن، إنجاز مهمة فعلية، إيقاف واستعادة وحذف مؤكد، دون بقايا موارد غير مبلّغ عنها.

### C05 — مشاهدة الجهاز والتولي اليدوي — جزئي، P1

- شاشة حية مع تحجيم صحيح ومؤشر واضح، ووضع مشاهدة منفصل عن التحكم.
- نقل التحكم للمستخدم وإعادته إلى المساعد دون تداخل إدخال.
- إيقاف فوري ومؤكد، ومفتاح طوارئ، وحالة انتظار تسجيل الدخول أو إدخال المستخدم.
- لوحة مفاتيح عربية، نوافذ وشاشات متعددة، رفع وتنزيل، وحافظة بموافقة ونطاق واضحين.
- سجل إجراءات ولقطات أدلة قابل للمراجعة دون كشف الأسرار.
- **القبول:** المستخدم يكمل تسجيل دخول يدويًا، يعود المساعد من الحالة الجديدة، ويوقف التولي جميع أفعال المهمة الجارية فعليًا.

### C06 — التحكم بجهاز المستخدم — جزئي، P1

- قراءة عناصر الإتاحة وDOM حيث يتوفران، ثم الرؤية وOCR عند الحاجة.
- فتح التطبيقات، اختيار النوافذ، الكتابة والنقر والسحب والمفاتيح والتعامل مع الحوارات.
- تحديد نطاق التطبيقات والملفات والمواقع المسموحة للمهمة.
- كشف تدخل المستخدم وتغير النافذة وفقدان التركيز، مع قفل حصري للسطح المكتبي.
- فحص النتيجة بعد كل إجراء مؤثر ومعالجة تغير الواجهة بدل تكرار نقر إحداثي أعمى.
- **القبول:** إنجاز سلسلة متعددة التطبيقات ثم إعادة فتح الملف الناتج والتحقق من محتواه، مع إثبات التوقف عند تدخل المستخدم.

### C07 — متصفح وحسابات مستقلة لكل مساعد — جزئي، P1

- ملف متصفح دائم داخل بيئة التنفيذ الصحيحة، مع فصل cookies والتخزين والتنزيلات.
- تبويبات وبحث ونماذج وجداول ورفع ملفات وتنزيلها ومواقع ديناميكية.
- تجديد الدخول بمساعدة المستخدم دون نسخ جلسة المضيف تلقائيًا.
- التعامل مع تغير DOM والتنقل الخلفي والأخطاء والانتظار، مع تتبع صفحة المهمة.
- التحقق من النتائج على الموقع وتجنب تكرار الإرسال عند إعادة المحاولة.
- **القبول:** مساعدان بحسابين في الخدمة نفسها يعملان بالتوازي دون اختلاط جلسات أو تنزيلات؛ يعمل متصفح own_device داخل جهازه فعلًا.

### C08 — التحكم الكامل بخدمات Loam — جزئي، P1

- كتالوج عمليات موحد يُشتق من الخدمة الفعلية: قراءة، إنشاء، تعديل، حفظ، استيراد، تصدير، إلغاء، متابعة، تحقق، واسترجاع حيث تدعم الخدمة.
- واجهات أدوات مُعرّفة ومدخلات متحققة، مع معرف مشروع وأصل وحساب ونسخة وصلاحية لكل عملية.
- النتائج مرئية وقابلة للتحرير في نفس واجهة الخدمة، ولا تُنشأ نسخ موازية غير متزامنة.
- دعم المهام الخلفية والأصول الكبيرة ونقلها دون تحميلها كلها في سياق النموذج.
- ربط جميع الخدمات الموجودة والجديدة ببوابة القدرات، مع اختبارات تغطية تمنع إسقاط العمليات بصمت.
- **القبول:** الرحلات في مصفوفة الخدمات أدناه تعمل من محادثة المساعد وتُفتح نتائجها وتُعدّل ويُعاد تصديرها من الواجهة.

### C09 — الفهم والتخطيط وإدارة الأهداف — جزئي، P1/P2

- تحويل الطلب إلى مخرجات ومعايير قبول وقيود واعتماديات واضحة.
- جمع السياق من المشروع والملفات والمحادثات وفق النطاق المصرح.
- تفكيك العمل وتقدير الموارد والوقت، واختيار الأدوات والنموذج المناسبين.
- إعادة التخطيط عند الفشل أو توجيه المستخدم، مع الاحتفاظ بالهدف الأصلي.
- أسئلة محدودة للقرارات اللازمة فقط، وتقدم مفهوم وأسباب واضحة للتعطل.
- **القبول:** مهمة طويلة يتغير أحد قيودها أثناء التنفيذ تنتهي بنتائج توافق الطلب المعدل دون فقد بقية المتطلبات.

### C10 — العمل الطويل والاستمرار بعد الإغلاق — جزئي، P1

- حفظ الرسائل الجديدة وتوجيهها للمهمة حتى بعد إعادة الاتصال، ومنع فقدها أو إرسالها مرتين.
- **القبول:** قطع الشبكة وإغلاق التطبيق وإعادة تشغيل العامل وسط المهمة لا يفقد البيانات ولا يعيد فعلًا خارجيًا مكتملًا.

### C11 — ذاكرة شخصية ومشروع وفريق — جزئي، P1/P2

- فصل نطاقات المستخدم والمساعد والمشروع والفريق والمهمة، مع فرض الوصول من التخزين.

- بحث نصي ودلالي مع توثيق الذكرى المستخدمة، ومعالجة التعارض والتقادم.
- مراجعة وتحرير ونسيان وتصدير واستيراد مع الحفاظ على العلاقات والتاريخ.

- **القبول:** تصحيح معلومة يزيل تأثير السابقة، والحذف يمنع استرجاعها، واستيراد مشروع لا يكشف بيانات مشروع آخر.

### C12 — التعلم من عرض المستخدم — جزئي/مطلوب، P2

- إعادة تشغيل المهارة على بيانات مختلفة وتغيرات واجهة معتدلة.

- عدم تعديل الصلاحيات أو النشر الذاتي لمهارة دون السياسة المحددة.
- **القبول:** تعليم إجراء مرة ثم تنفيذه على أمثلة جديدة واجتياز تحقق مستقل.

### C13 — صوت عربي طبيعي قابل للمقاطعة — جزئي، P2

- محادثة مستمرة مع كشف الكلام والصمت والضجيج والصدى.
- نطق متدفق دون تكرار أو فقد جمل، ومقاطعة توقف الصوت والعمل وفق طلب المستخدم.

- تفريغ مؤرخ يميز المتحدثين وتصحيح النص ووصول واضح لحالة الميكروفون.
- **القبول:** اختبار ميكروفون ومكبر حقيقيين، بمقاطعة قبل أول رمز وأثناء الكلام وبعد إعادة الاتصال، وقياس التأخير ودقة التفريغ.

### C14 — فهم الصور والصوت والفيديو والشاشة — جزئي، P2

- قراءة صور وPDF ومسح ضوئي وجداول ورسومات، مع OCR عربي.
- فهم فيديو بتوقيتات ومشاهد، وتفريغ صوت وربط الملاحظات بالزمن.
- متابعة شاشة أو كاميرا أثناء الطلب ضمن صلاحيات مرئية.
- التعامل مع ملفات كبيرة بتجزئة وفهرسة واسترجاع للأجزاء المطلوبة.
- إنتاج ملفات متعددة الوسائط قابلة للتحرير، مع ذكر حدود جودة الاستدلال.
- **القبول:** تحليل فيديو حقيقي، تحديد مقاطع بالتوقيت، تحريرها في صمّم ثم تصدير ملف قابل للتشغيل والتحقق.

### C15 — فرق مساعدين وتفويض منظم — جزئي، P2

- أدوار ومسؤوليات ومالك للمهمة ومدخلات ومخرجات وشروط قبول لكل تفويض.
- أجهزة وحسابات وذاكرة منفصلة مع مشاركة صريحة للأصول.
- رسائل داخلية واعتماديات ومتابعة تقدم وإلغاء ينتقل للأعمال التابعة.
- منع دورات التفويض والانفجار في التكلفة، وجدولة التوازي وفق الموارد.
- دمج النتائج وحل التعارضات ومراجعة مستقلة قبل التسليم للمستخدم.
- **القبول:** باحث ومبرمج ومصمم ومراجع ينفذون مشروعًا واحدًا بأجهزة منفصلة، ويتعاملون مع فشل عضو دون خسارة بقية العمل.

### C16 — المبادرة والروتينات والأحداث — جزئي، P2

- جداول زمنية بمناطق زمنية وأيام عمل وتكرار ومدة انتهاء.
- محفزات ملفات وبريد وتقويم وطلبات مراجعة وخدمات وwebhooks وفق الحسابات الممنوحة.
- منع تكرار الحدث ودمج الأحداث المتقاربة وتسوية الأحداث الفائتة بعد التوقف.
- ساعات هدوء وأولويات وتنبيه عند تغير مهم فقط.
- إيقاف جميع المحفزات فور تعليق المساعد أو أرشفته أو إلغاء صلاحياته.
- **القبول:** حدث واحد يولد عملًا واحدًا؛ لا تشغيل بعد الأرشفة؛ تستعاد الأحداث وفق سياسة معلنة بعد الانقطاع.

### C17 — الحسابات والخدمات الخارجية — جزئي، P1/P2

- إدارة عدة حسابات لكل خدمة وربط كل حساب بمساعد أو مشروع صراحة.
- صلاحيات قراءة وكتابة وإرسال منفصلة، وتجديد الرموز وإلغاء الوصول.
- أدوات للبريد والتقويم والملفات وإدارة العمل والمستودعات وفق الخدمات التي يختارها المستخدم.
- دعم MCP وواجهات الخدمات والمتصفح عندما يلزم، مع وصف موثوق للقدرات.
- سجل عمليات لكل حساب ومنع خلط حساب العمل والشخصي أو إرسال نسخة مكررة.
- **القبول:** المهمة تستخدم الحساب المختار فقط؛ إلغاء منحه يمنع الاستدعاءات التالية وكل الأعمال المجدولة التابعة.

### C18 — الأمان والخصوصية والصلاحيات — جزئي، P0/P1

- صلاحيات قابلة للفرض في الخادم على مستوى العملية والموارد، لا تعليمات prompt وحدها.
- خزنة أسرار لكل مالك، وحقن محدود للأسرار مع حجب السجلات والأخطاء والآثار المصدرة.
- عزل نظام وشبكة وحافظة وملفات وحسابات، مع جسور مشاركة واضحة.
- معاملة محتوى الويب والملفات كبيانات غير موثوقة وعدم السماح له بتغيير تعليمات المستخدم.
- موافقات مرتبطة بالفعل والهدف والنطاق، مع مدة وصلاحية وإبطال؛ لا موافقات متكررة للعمل المصرح نفسه.
- تشفير واحتفاظ وحذف ونسخ احتياطي وسجل مراجعة وإعدادات مناسبة لبيانات الفرق.
- **القبول:** اختبارات سلبية حقيقية تمنع تسرب بيانات بين المساعدين أو تجاوز المنح أو تنفيذ تعليمات مدسوسة في ملف.

### C19 — نماذج وتكلفة وجودة استدلال — جزئي، P2

- اختيار نماذج نص ورؤية وصوت وبرمجة حسب المهمة والخصوصية والميزانية.
- قياس اختيار النموذج على جودة فعلية، وتصعيد المهمة الصعبة عند الحاجة.
- بدائل عند تعطل المزود، ومعالجة حدود الطلبات والسياق والأخطاء دون فقد المهمة.
- تكلفة فعلية للنماذج والأجهزة والتخزين، وحدود لكل مهمة ومساعد وفريق.
- تخزين مؤقت واسترجاع سياق منضبط، ووضع محلي عند توفر قدرات مناسبة.
- **القبول:** تقرير يربط الجودة والوقت والتكلفة بالنموذج؛ تجاوز الميزانية يوقف أو يطلب قرارًا وفق السياسة ولا يستمر بصمت.

### C20 — تحقق مستقل وإصلاح تلقائي — جزئي، P1/P2

- فاحص نهائي يعتمد شروط القبول وحالة النظام والملف الناتج.
- فتح المستندات وتشغيل التطبيقات والفيديو وفحص الصيغ والروابط والحسابات.
- فصل أدلة الاختبار عن وصف المساعد لعمله، ومنع تعديل المقيّم أو بياناته.
- إصلاح موجّه بعد الفشل بحدود للمحاولات والتكلفة، ثم تصعيد واضح عند التعذر.
- مقارنة بصرية ووظيفية وحفظ الإصدارات وإمكان التراجع.
- **القبول:** ناتج ناقص عمدًا يفشل حتى لو أعلن المنفذ اكتماله؛ الإصلاح التالي يُعاد التحقق منه مستقلًا.

### C21 — واجهة إنتاج كاملة — جزئي، P1

- صفحة مساعد تجمع المحادثة والجهاز والمهام والملفات والذاكرة والمهارات والروتينات والحسابات والتكلفة.
- أزرار كل عمليات الهوية والأجهزة والخدمات الموجهة للمستخدم.

- **القبول:** مستخدم جديد ينجز دورة كاملة من الإنشاء إلى التسليم والاستعادة دون CLI أو تعديل إعدادات يدويًا.

### C22 — الهاتف والمزامنة وقنوات التواصل — جزئي/مطلوب، P2

- معالجة انقطاع الهاتف وتعدد الأجهزة وتعارض الرسائل دون فقد أو تكرار.
- **القبول:** بدء مهمة من الهاتف ومتابعتها على سطح المكتب، ثم إيقافها من الهاتف مع أثر مؤكد على العامل.

### C23 — الاعتمادية والتشغيل والتوسع — جزئي، P1/P2

- عمال مراقبون وheartbeat وleases وأقفال بمهلة تمنع عاملًا قديمًا من الكتابة بعد استبداله.

- صحة وقياسات وتتبع أخطاء وتكلفة ووقت لكل مرحلة، وتنبيهات تشغيل مفيدة.

- **القبول:** إعادة تشغيل وقطع شبكة وامتلاء قرص وتعطل عامل تُنتج استعادة أو فشلًا مفهومًا، دون فساد بيانات أو استمرار عاملين متنافسين.

### C24 — إثبات مستوى Frontier والمقارنة العادلة — غير مقاس، P3 يبدأ مبكرًا

| المهام والمشاريع | إنشاء وتشغيل وتبعيات ومتابعة وإلغاء واستكمال وتسليم | الحالة صحيحة بعد الإغلاق وإعادة الاتصال وتغيير المالك |
| الأتمتة | جداول وأحداث وإشعارات وتعطيل ومنع تكرار | حدث واحد، عمل واحد، وإيقاف شامل عند تعليق المساعد |
| الخدمات المتصلة | حسابات وصلاحيات وقراءة وكتابة وتنفيذ ومتابعة نتائج | استخدام الحساب المقصود مع احترام المنح وسحبها والتعامل مع انقطاع الخدمة |

### فجوات الربط الحالية ذات الأولوية

- `loam_creative` يقرأ/يستبدل مشهد 3D، و`loam_canvas` ينتج SVG؛ لا يغطيان كامل واجهات timeline والصور والأصول ووظائف التصدير الخلفية.
- `loam_studio` يقدم قراءة/استبدال/إلحاق؛ يلزم ربط الاستيراد والتصدير الأصلي والمعاينات بالقدرات التي تملكها خدمة الأوفيس بالفعل.
- أدوات `pentest_*` ليست بديلًا كاملًا عن دورة `/api/security/assessments` والفرز وإعادة الاختبار والإصلاح.
- `super_* / metagpt_company` لا يثبتان تكامل دورة `/api/swarm/runs` الحالية.
- إتاحة المجموعة يجب أن تكون مشتقة من أدوات الجولة النهائية والجاهزية، لا التسجيل والمنح وحدهما.
- `task_create` ينشئ سجلًا دون تشغيل، ولا يوجد تكامل أدوات كامل للتشغيل والاستئناف؛ كما يحتاج مرشح `mineOnly` إلى المقارنة بمعرف المساعد الحالي (`src/tools/loamServices.ts:55`).
- مثال على إتاحة غير دقيقة: `pentest_*` مسجلة ضمن مجموعة الأمن لكنها لا تدخل الأدوات النهائية عبر الأنماط والمنح الحالية؛ يجب اختبار إتاحتها في الجولة نفسها.

| العنصر | المواصفة |

| النظام | بيئة معزولة قابلة للتشغيل؛ Windows/Linux حسب المزود المعلن |
| التخزين | قرص دائم أو مؤقت، حصص، تشفير، نسخ احتياطي، نقل صريح للأصول |
| الحسابات | متصفح وخزنة وحسابات منفصلة؛ لا مشاركة تلقائية بين المساعدين |
| العمل | عامل داخل البيئة يتتبع عمليات المهمة ويستطيع تأكيد إلغاء مجموعتها |
| المشاهدة | سطح مكتب حي وتولّي وإعادة تحكم وسجل أحداث |
| الموارد | حصص فعلية للمعالج والذاكرة والقرص والشبكة وGPU عند الدعم |
| دورة الحياة | إنشاء→تجهيز→جاهز→مشغول/تولّي يدوي→متوقف؛ فشل قابل للاستعادة؛ حذف مؤكد |
| التوازي | قفل لكل جهاز؛ مهام أجهزة مختلفة تتوازى؛ المشاركة استثناء صريح |

الاختبار الحاسم: ثلاثة مساعدين على ثلاثة أجهزة حقيقية؛ باحث ينتج تقريرًا، مبرمج ينتج تطبيقًا مجربًا، ومحرر ينتج فيديو قابلًا للتشغيل. يُغلق التطبيق أثناء التنفيذ ثم يُفتح، ويتولى المستخدم أحد الأجهزة ثم يعيد التحكم، وتُفحص النتائج والحسابات والعزل والإلغاء. لا يستبدل هذا الاختبار بثلاثة ملفات نصية تحمل أسماء أدوار مختلفة.

## عقد التنفيذ والبيانات

- الكيانات: Assistant، Device، Task، Run، Action، Approval، AccountGrant، SecretRef، Memory، Project، Artifact، Schedule، Event، Evaluation، UsageRecord. كل منها له مالك وإصدار وتوقيت وحالة.
- أوامر الخدمات تحمل معرفات المساعد والمهمة والمشروع والوجهة، ومدخلات متحققة، ومفتاح منع التكرار حيث يلزم، وإشارة إلغاء.
- الاستجابة تعيد حالة ونتائج ومعرفات ملفات/مشاريع وأدلة تحقق واستهلاكًا وأخطاء قابلة للفهم؛ العمليات الطويلة تعيد jobId وتدعم المتابعة والإلغاء.
- حالات المهمة: مسودة→في الطابور→تعمل→تنتظر موردًا/موافقة/تسجيل دخول أو تتوقف مؤقتًا→اكتملت بتحقق/فشلت/أُلغيت. حالة الإلغاء المطلوبة منفصلة عن الإلغاء المؤكد.
- حالة الأرشفة لا تزيل البيانات، لكنها تمنع مشغلات العمل وفق السياسة؛ الحذف إجراء مستقل.
- نقل مشروع يحدد الأصول والذاكرة والصلاحيات المنقولة صراحة، ويحافظ على العلاقات وسجل المصدر.
- تحديثات المخطط والاستيراد لها تحقق وتقرير فروق ونسخة يمكن الرجوع إليها؛ واجهة التطبيق والنموذج يستخدمان نفس قواعد الأعمال.
- مؤشرات التشغيل: نجاح وتدخلات وزمن انتظار/تنفيذ/تحقق وتكلفة وأخطاء وإلغاء غير مؤكد وسلامة عزل، مع سجل لا يكشف الأسرار.

## بوابات قبول مقترحة

الأرقام التالية مقترحات لتثبيت أهداف المنتج بعد تحديد العتاد والمزودين والمهام المرجعية:

1. **بوابة الصحة:** إغلاق F01–F13 باختبارات إعادة إنتاج مستقلة؛ لا عيب مانع معروف في الإلغاء أو فقد البيانات أو تجاوز الصلاحيات.
2. **بوابة الاستخدام:** كل عملية معلنة في الكتالوج لها مسار واجهة واختبار نجاح وفشل وصلاحيات وإلغاء/استعادة حيث تنطبق.
3. **بوابة الاستقلال:** نجاح دورة الأجهزة الثلاثة الحقيقية والعزل والتولي، مع إثبات توقف الكتابة/الإرسال بعد إقرار الإلغاء.
4. **بوابة الاعتمادية:** 100 سيناريو انقطاع/استعادة على بيانات اختبار دون فقد أو تكرار أثر خارجي في العينة. لا تعني النتيجة ضمانًا مطلقًا.
5. **بوابة الجودة:** 200 مهمة ممثلة، مع مجموعة مخفية وتكرار للتجارب المتغيرة. هدف أولي مقترح ≥90% إنجاز صحيح في مجموعة الاستخدام الأساسية المتفق عليها، مع تقرير منفصل لكل مجال. ليست هذه نسبة إنجاز النظام الحالية أو شرطًا رسميًا للمعايير العامة.
6. **بوابة الأداء:** تحديد أهداف p50/p95 للاستجابة الأولى والصوت وتولّي الجهاز وإلغاء العمل لكل مزود؛ لا يُعلن رقم قبل تحديد ظروف القياس وإثباته.
7. **بوابة المقارنة:** تشغيل المنافسين على نفس المهام، إظهار النتائج غير المتاحة كغير مقاسة، ومقارنة الجودة والوقت والتكلفة والتدخلات معًا. يُعلن التفوق في الفئات التي تثبته فقط.

## قرارات تحتاج تثبيتًا قبل تنفيذ الأجزاء المعتمدة عليها

- الحد الأولي لعدد المساعدين والأجهزة المتزامنة وعتاد الجهاز المضيف.
- أنظمة الضيف المطلوبة أولًا: Linux أو Windows، ثم المزود السحابي وموقع البيانات إن اختير.
- الميزانية الشهرية للنماذج والأجهزة والتخزين، ومن يحدد حدود المهمة.
- الحسابات الخارجية والقنوات ذات الأولوية وسياسة مشاركة حساب واحد بين المساعدين.
- قواعد الاستقلال والاحتفاظ بالبيانات والأسرار لكل نوع عمل.
- المنتج والإصدار المقصودان باسم Dot عند تثبيت المقارنة، وسائر المنافسين المتاح اختبارهم فعليًا.

لا تمنع هذه القرارات بدء إصلاحات الصحة أو بناء كتالوج القدرات واختبارات الخدمات. أما اختيار تقنية الأجهزة والسحابة وحصص التوسع فيحتاج مراجعة معمارية وقياس العتاد. التنفيذ المباشر التالي: مرحلة A، ثم تجربة جهاز Linux واحد حقيقي داخل الواجهة قبل تعميم المزودين أو ادعاء أجهزة مستقلة لكل مساعد.
