# استوديو تطبيقات الجوال

المسار `#/studios/mobile` يفتح مساحة بناء تتمحور حول معاينة الهاتف. وضع «تجربة التطبيق» يشغّل الأزرار والحقول؛ وضع «تعديل بالنقر» يحدد عنصرًا لعرض محرره في اللوحة الجانبية. ويمكن تحديد العناصر من قائمة الشاشة باستخدام لوحة المفاتيح. التغييرات تظهر فورًا، والحفظ صريح. إطارا iOS وAndroid عرض بصري فقط.

زر «ملء الشاشة» يوسّع مساحة المعاينة لتملأ نافذة التطبيق، مع بقاء إطار الهاتف نفسه دون إعادة تحميله. زر «العودة للاستوديو» أو Esc يعيد المحرر؛ اختيار «تعديل بالنقر» يعيد لوحة التحرير أيضًا. تحتفظ المعاينة بالصفحة ومسار الرجوع وقيم الحقول. الأجزاء الخلفية غير قابلة للتركيز أثناء التوسيع. هذا وضع ملء نافذة التطبيق، وليس إخفاء واجهة نظام التشغيل.

أشرطة المحرر مدمجة لزيادة ارتفاع الهاتف. الصفحات الرئيسية التي تحتوي وجهات فقط تعرض شبكة عمودين عند توفر العرض، وتبقى الصفحات المختلطة والضيقة بقائمة واحدة. النصائح في الصفحات الرئيسية قابلة للفتح لتقديم الوجهات أولًا، مع إبقاء التنقل الرئيسي ظاهرًا.

المشاريع معزولة حسب مهمة Build داخل `.loam/mobile.json`. يدعم المشروع 100 شاشة، و60 عنصرًا في الشاشة: عنوان، نص، حقل، مفتاح اختيار، وزر انتقال أو حفظ محلي. لا يحتاج التحرير اليدوي إلى نموذج.

## الشاشات والتنقل
يفتح زر «الشاشات» مستكشفًا بالبحث في الاسم والمجموعة، ومجموعات قابلة للطي، ومفضلة وآخر ثماني صفحات. يظهر مسار الصفحة فوق الهاتف، ويمكن النقر على أي صفحة أم لفتحها. تبقى المعاينة مركز العمل عند إغلاق المستكشف.

لكل شاشة group وkind؛ نوع primary يظهر في التنقل الرئيسي (قسم واحد إلى خمسة)، ونوع detail له parentId وزر رجوع. يرجع التطبيق إلى الصفحة التي جاء منها المستخدم، أو الصفحة الأم عند فتح صفحة مباشرة من المستكشف. الانتقال إلى قسم رئيسي يبدأ مسار رجوع جديدًا. تغيير المجموعة لا يغير بنية التنقل. المشاريع القديمة دون بيانات تنقل تُقرأ تلقائيًا: أول خمس صفحات رئيسية والبقية فرعية للأولى؛ تكشف الخريطة أي صفحات تحتاج روابط وصول.

خريطة التدفق قابلة للتصفية حسب القسم وتعرض بنية الصفحات وروابط الأزرار الفعلية. يمكن فتح الصفحة أو وجهة الرابط منها، وتظهر رسالة للصفحات التي لا يصل إليها أي مسار من الأقسام الرئيسية. parentId يوفر الرجوع فقط؛ يلزم زر انتقال للوصول إلى الصفحة الفرعية. يمنع الحفظ دورات الآباء والروابط المفقودة. عند حذف صفحة تُحذف أزرار الانتقال إليها وتُنقل صفحاتها الفرعية إلى أمها أو قسم رئيسي؛ التراجع يستعيد ذلك كله.

الحد الأقصى لحجم بيانات المشروع 2.5 MB، مع إبقاء تاريخ النسخ منفصلًا عن هذا القياس.

## البناء والإصلاح

`POST /api/mobile/build` مسار مخصص يستدعي النموذج المحدد عبر Ollama مباشرة، دون دورة التخطيط العامة أو تبديل النموذج خفية. يرسل المشروع الحالي والطلب ثم يفحص JSON والمعرفات والأنواع والروابط. أخطاء المسودة تعود للنموذج للتصحيح، بحد أقصى ثلاث محاولات. المسودة غير الصالحة لا تُحفظ. هذه فحوص بنيوية وليست إثباتًا لاكتمال كل متطلبات المستخدم أو اختبارًا آليًا لسلوك الجهاز.

مخطط التوليد يطلب `sections` للأقسام الرئيسية (1–5) و`pages` للصفحات الفرعية مع `parentId` إلزامي، ثم يحوّلهما الخادم إلى صيغة `screens` المحفوظة. يختار النموذج المعرفات والمحتوى والآباء والروابط؛ التحويل يحدد النوع من المجموعة فقط. يُرفض البناء الكامل إن لم يضع النموذج زر انتقال في كل صفحة أم إلى أبنائها، وتُعاد المشكلة إليه للتصحيح. الحفظ اليدوي يظل يسمح بمسودات غير موصولة ويعرض تحذيرها في الخريطة.

عند تحديد عنصر، يطلب المسار تغيير نصه أو وجهة زره فقط. يطبّق الخادم التغيير على العنصر المحدد، ويحافظ على بقية المشروع. إلغاء الطلب يقطع الاستدلال، ويُفحص الإلغاء قبل الحفظ. رقم expectedRevision يمنع الرد المتأخر من تجاوز تعديل أحدث. طلبات البناء المتزامنة للمشروع نفسه تُرفض.

## التصميم والمحتوى

يطلب التوليد الجديد من النموذج وصفًا موجزًا وغرضًا ونصيحة عملية وأيقونة لكل صفحة. يعرضها التطبيق في مقدمة واضحة، وبطاقات للانتقال تحتوي وصف الوجهة، وبطاقة إرشاد. الحقول تدعم نصًا مساعدًا وأمثلة داخل الحقل لا تُحفظ كبيانات. مؤشر التقدم في القسم يُحسب من مفاتيح الإنجاز الفعلية في صفحاته الفرعية؛ لا ينشئ إحصاءات افتراضية.

زر «حسّن التصميم والمحتوى» يستدعي النموذج المختار لكل صفحة عبر `operation: 'polish'`، ويحسّن النصوص والعرض فقط. قائمة التغييرات المسموحة لا تشمل معرفات الصفحات والحقول أو أنواعها أو روابطها أو الآباء. يجمع الخادم النتيجة ويفحصها قبل حفظ نسخة واحدة؛ الفشل أو الإلغاء لا يحفظ تحسينًا جزئيًا. تعارض رقم المراجعة يمنع تجاوز تعديل أحدث. يمكن التراجع عن التحسين وإعادته، وتظل قيم المستخدم مرتبطة بمعرفاتها الأصلية.

يمكن تحرير المقدمات والإرشادات من إعدادات الشاشة، وتحرير النص المساعد والمثال من تفاصيل العنصر. تظهر هذه البيانات في معاينة الويب والتصدير المستقل ومصدر Expo.

يفحص البناء والتحسين أسماء الإجراءات: تُرفض أزرار الحفظ العامة بلا اسم للمحتوى المحفوظ، ومفاتيح الإنجاز التي تقول «مكتملة» فقط، وأزرار الانتقال المسماة حفظًا، وتسرب بعض أسماء عناصر البرمجة إلى النص العربي. يتلقى النموذج الرد المرفوض وسبب رفضه للتصحيح. المقدمة التي تكرر عنوان الصفحة تُحجب في عارض الويب. هذه قواعد تحرير محددة، وليست ضمانًا آليًا لجودة كل جملة؛ تبقى مراجعة النصوص الناتجة مطلوبة.

## التراجع

يحفظ الملف نفسه تاريخًا ذريًا لآخر ثماني نسخ، مع مسار للإعادة. `POST /api/mobile/undo` و`/redo` يتطلبان taskId وexpectedRevision. الاستعادة تزيد رقم المراجعة وتحافظ على حماية التعارض. يبقى التاريخ بعد إعادة تشغيل الخادم؛ وتغيير جديد يمحو فرع الإعادة. في المحرر، التغييرات غير المحفوظة لها تراجع محلي أيضًا؛ العودة إلى مشروع آخر تتطلب حفظها أو تركها صراحة.

## API والتصدير

GET/POST `/api/mobile`، GET `/api/mobile/projects`، GET `/api/mobile/preview`، GET `/api/mobile/export`. طلبات الكتابة من نفس المصدر وفي مهام Build فقط. المعاينة داخل المحرر تتبادل رسائل مع إطار من نفس المصدر مع التحقق من المصدر والنافذة، وتستخدم نفس عارض تطبيق الويب المصدّر.

ZIP يضم تطبيق ويب مستقلًا وJSON ومصدر Expo. لا يتضمن بناء APK/IPA أو توقيعًا أو نشر متجر. مصدر Expo يستخدم خط أساس SDK 53 / React 19 / RN 0.79، ويحتاج تثبيت الحزم وفحصها وبناء واختبار الجهاز. المصادقة والدفع والمزامنة والخدمات الخلفية غير منفذة في مخطط الشاشات؛ الحقول تُحفظ على الجهاز فقط.

## التحقق

- `npm run check:mobile`: خادم فعلي وEdge مع نموذج حتمي؛ الأداة وHTTP والعزل والتعارض، التحرير بالنقر، الحفظ والتراجع والإعادة بعد إعادة التحميل، توليد وتصحيح المسودة وتعديل العنصر، الحقول والتنقل والتصدير والتجاوب.
- `npx tsx src/scripts/check-mobile-build.ts`: حد محاولات الإصلاح، عدم حفظ المسودة الفاشلة، الإلغاء، الرد المتأخر، حصر تعديل العنصر، التاريخ وإلغاء فرع الإعادة.
- `npx tsx src/scripts/check-mobile-http.ts --bundle`: نفس اختبار التكامل على حزمة الخادم بعد بنائها.
- `npx tsx src/scripts/check-mobile-polish.ts`: حصر تحسين المحتوى، حفظ جميع الصفحات دفعة واحدة، الإصلاح والإلغاء والتعارض والتراجع.
- `npx tsx src/scripts/check-mobile-preview-layout.ts`: ظهور بطاقات الأقسام الأربع، توسيع المعاينة والخروج بـEsc، بقاء الصفحة والرجوع والبيانات، التحرير، والتجاوب. نتيجة نافذة 1110×884: ارتفاع محتوى الهاتف 534 بكسل عاديًا و776 بكسل عند التوسيع. الأدلة في `release/mobile-live/preview-layout/`.
- `npx tsx src/scripts/check-mobile-generated.ts <taskId> --polished`: اختبار التطبيق الحي ذي عشرين صفحة بعد تحسينه، ومقارنة البنية بلقطة `release/mobile-live/polished-app/before.json`، والتقدم الحقيقي وحفظ الحقول والتصدير. يستخدم بيانات متصفح اختبار منفصلة؛ يختبر تراجع المشروع ثم يعيده إلى النسخة المحسنة.

هذه الاختبارات لا تستبدل التجربة الحية بنموذج محلي، ولا تختبر جهاز iOS/Android أصليًا.

The local-model path uses Ollama's optional JSON-schema `format` support. The implementation was checked against https://docs.ollama.com/capabilities/structured-outputs . Models explicitly marked cloud use prompt-driven JSON with the same validation/repair loop instead. Save-labelled buttons that navigate are returned for repair; this check is limited to Arabic/English save labels and does not infer every possible app behavior.
