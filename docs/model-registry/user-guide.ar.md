# دليل المستخدم: سجل النماذج الموحد

## نظرة عامة

سجل النماذج الموحد يتيح لك إضافة وإدارة أي مزود نماذج:
- **محلي**: Ollama, LM Studio, llama.cpp server
- **سحابي**: OpenAI, OpenRouter, Anthropic, Google Gemini, LongCat, OpenCode Go, FreeLLMAPI
- **مخصص**: أي نقطة نهاية متوافقة مع OpenAI

## البدء السريع

### 1. الترقية التلقائية

عند التشغيل الأول بعد التحديث، سيقوم Loam تلقائيًا بـ:
- ترحيل إعداداتك من `config.json`
- نقل مفاتيح API إلى مخزن آمن (Windows DPAPI)
- إنشاء نسخة احتياطية: `config.json.pre-registry.bak`
- إنشاء `data/model-registry.json`

### 2. فتح إعدادات النماذج

1. افتح **الإعدادات** > **النماذج**
2. سترى قائمة بمقدمي الخدمة والنماذج المتاحة

### 3. إضافة مزود جديد

#### إضافة Ollama (محلي):
- مثبت بالفعل إذا كنت تستخدم Ollama
- عنوان URL الافتراضي: `http://127.0.0.1:11434`
- لا يتطلب مفتاح API

#### إضافة OpenAI:
1. انقر **إضافة مقدم خدمة**
2. اختر **OpenAI** من القائمة
3. أدخل مفتاح API الخاص بك (يبدأ بـ `sk-`)
4. انقر **حفظ**

#### إضافة Anthropic:
1. انقر **إضافة مقدم خدمة**
2. اختر **Anthropic**
3. أدخل مفتاح API
4. انقر **حفظ**

#### إضافة Google Gemini:
1. انقر **إضافة مقدم خدمة**
2. اختر **Google Gemini**
3. أدخل مفتاح API (يبدأ بـ `AIza`)
4. انقر **حفظ**

#### إضافة مزود مخصص:
1. انقر **إضافة مقدم خدمة**
2. اختر **مخصص**
3. أدخل:
   - **الاسم**: اسم وصفي
   - **عنوان URL**: نقطة النهاية (مثل `https://api.example.com/v1`)
   - **مفتاح API**: اختياري
   - **النوع**: OpenAI-compatible, Anthropic, أو Gemini
4. انقر **حفظ**

## إدارة النماذج

### اكتشاف النماذج تلقائيًا

بعد إضافة مزود:
1. انقر على بطاقة المزود
2. انقر **اكتشاف النماذج**
3. سيقوم Loam بالاتصال بالمزود وجلب قائمة النماذج

### تفعيل/تعطيل النماذج

- انقر على بطاقة النموذج
- بدّل حالة **مفعّل/معطل**
- النماذج المعطلة لن تظهر في قائمة الاختيار

### تكوين القدرات

لكل نموذج، يمكنك تحديد:
- **الأدوات**: دعم استدعاء الوظائف
- **الرؤية**: دعم الصور
- **التفكير**: وضع التفكير (بدون، اختياري، دائمًا)
- **حجم السياق**: عدد الرموز
- **حد المخرجات**: أقصى رموز الإكمال

## السلاسل (Failover)

السلاسل تحدد ترتيب المحاولة للنماذج:

### السلسلة الافتراضية
- تُستخدم لجميع المهام العامة
- يحاول Loam النماذج بالترتيب
- عند الفشل (401, 429, خطأ)، ينتقل إلى النموذج التالي

### سلسلة البرمجة
- تُستخدم للمهام البرمجية
- يمكن تكوين نماذج مختلفة للبرمجة
- أولوية للنماذج الأقوى

### إنشاء سلسلة مخصصة
1. انتقل إلى قسم **السلاسل**
2. انقر **إنشاء سلسلة**
3. اسحب النماذج لترتيبها
4. احفظ

## الأمان

### تخزين مفاتيح API

- **وضع سطح المكتب**: مفاتيح مشفرة بـ Windows DPAPI في `%APPDATA%/manus-local/model-secrets/`
- **الوضع السحابي**: استخدم متغيرات البيئة (لا تخزين محلي)

### تدقيق المفاتيح

- لن تظهر المفاتيح أبدًا في واجهة المستخدم
- لن تظهر في السجلات
- لن تُحفظ في `config.json`
- تُحذف عند إزالة المزود

### النسخ الاحتياطي

يُنشئ Loam نسخًا احتياطية:
- `config.json.pre-registry.bak`: قبل الترقية
- `model-registry.json.bak`: قبل كل حفظ

## استكشاف الأخطاء

### "فشل تحميل السجل"
- تحقق من ملف `data/model-registry.json`
- إذا كان تالفًا، احذفه وأعد تشغيل Loam (سيعيد الترحيل)

### "فشلت المصادقة (401)"
- تحقق من صحة مفتاح API
- قد يكون المفتاح منتهي الصلاحية أو محذوفًا
- حدّث المزود بمفتاح جديد

### "عدد كبير من الطلبات (429)"
- وصلت إلى حد السعر
- سيحاول Loam النموذج التالي في السلسلة
- انتظر أو استخدم مزود آخر

### "النموذج غير موجود (404)"
- تحقق من صحة اسم النموذج
- قد يكون النموذج غير متاح لحسابك
- جرب اكتشاف النماذج مرة أخرى

## الأسئلة الشائعة

### هل يمكنني استخدام عدة مفاتيح لنفس المزود؟
لا، الإصدار 1 يدعم مفتاح واحد لكل مزود. لاستخدام عدة مفاتيح، أضف نفس المزود عدة مرات بأسماء مختلفة.

### هل يدعم Loam النماذج المحلية الأخرى؟
نعم! أي خادم متوافق مع OpenAI يعمل (LM Studio, llama.cpp, text-generation-webui, vLLM, إلخ).

### كيف أحدث النماذج المتاحة؟
انقر **تحديث** في شاشة النماذج، أو استخدم `/api/model-registry/reload` في API.

### هل تُدعم نماذج الرؤية؟
نعم! حدد **الرؤية: مدعوم** في إعدادات النموذج. يدعم Loam نماذج الرؤية من Gemini و GPT-4o و Claude.

## English Quick Reference

- **Settings > Models**: Open registry UI
- **Add Provider**: Click button, choose preset or custom
- **API Keys**: Stored encrypted in Windows DPAPI
- **Chains**: Define failover order (default, coding, custom)
- **Discovery**: Auto-fetch model list from provider
- **Backup**: `config.json.pre-registry.bak` created on first run
