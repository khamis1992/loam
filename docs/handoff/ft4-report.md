# ft4 — FRONTIER V4 deepen (auto-captions / auto-reframe / scene-detect / auto-clip)

The four V4 pipelines in `src/creative/auto.ts` now run both before and after a deepening pass: scene detection, energy-weighted highlight clipping (long→short), subject-aware reframing, and transcript cue building were already complete pure functions over the timeline/plan model, and this round added (1) `adaptiveThreshold()` — a median+k×MAD cut threshold (clamped 0.05..0.8, 0.02 pad when MAD is dead-flat, 0.35 fallback with <2 samples) that separates subtle cuts from low-noise footage where the static 0.35 sees nothing while never flagging constant noise; (2) `snapToBeats()` plus optional `beats`/`beatsTolerance` on `pickHighlights` and `planAutoEdit` — CapCut-style beat-sync that snaps clip starts to the nearest music beat within tolerance, keeping ends fixed and reverting any snap that would truncate below minKeep; (3) a capped-speed reframe pan — optional `maxPan` (frame-fraction per second) + `panTickSeconds` on `computeReframe`/`AutoEditOptions` that walks the crop origin on a pursuit grid so the portrait pan never jumps to the subject keyframe position (capped per-tick steps, contiguity preserved, static stretches merged); and (4) caption infrastructure — `toSrt()`/`toVtt()` exporters with `hh:mm:ss,mmm` / `hh:mm:ss.mmm` stamps and `captionsForRange()` which rebases a cue list onto any highlight window (clamped, shifted, re-indexed, monotonic, sliver-culling below `minKeep`) so auto-clip and auto-captions compose into short-form deliverables. All new behavior is additive and default-preserving: without the new option keys every previous output is byte-identical (verified by the untouched original 21 assertions). `AutoEditOptions` gained `adaptive/sensitivity/maxPan/panTickSeconds/beats/beatsTolerance` pass-throughs in `planAutoEdit`, including a thread-once integration test; the route-level sanitizer in `src/server/routes/autoVideo.ts` (sibling worker's file) was deliberately left untouched.
