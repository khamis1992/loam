# Reviewed HTML-insertion repair — revision 40

Source assessment now adds AST-based review candidates for direct JavaScript/TypeScript `.insertAdjacentHTML(...)` calls. Comments and string literals containing that spelling are not calls. The rule does not perform taint analysis or prove that the receiver is a DOM Element; static candidates still require review of data provenance, sanitization and intended HTML behavior.

For an eligible candidate, the existing repair workflow can propose changing only the method token from `insertAdjacentHTML` to `insertAdjacentText`. Both arguments and the receiver remain unchanged. Eligibility requires exactly two arguments, no spreads or optional call, and a literal position from `beforebegin`, `afterbegin`, `beforeend`, `afterend` (case-insensitive). Unsupported position expressions and ambiguous multiple supported operations on the same reported line are rejected. This deliberately renders the supplied value as text; an application requiring formatted HTML needs a different reviewed solution.

The shared scanned-hash, UTF-8, AST parsing, review, backup, concurrent-edit, pending-operation recovery and rollback guards also protect this repair. The UI displays the actual before/after tokens from each draft rather than hardcoding `innerHTML → textContent`. Static disappearance alone remains unverified and never automatically closes a finding.

Standards used for the intended DOM behavior: [WHATWG DOM insertAdjacentText](https://dom.spec.whatwg.org/#dom-element-insertadjacenttext) and [WHATWG HTML insertAdjacentHTML](https://html.spec.whatwg.org/multipage/dynamic-markup-insertion.html#dom-element-insertadjacenthtml). Replacing HTML insertion with text insertion is suitable only when plain text is the intended output; it is not a sanitizer or a general XSS repair.

`src/scripts/check-security-insertion-repair.ts` serves a local application and runs actual Chrome campaigns for all four positions. Each case demonstrates fragment-canary execution, prepares a draft without changing source, applies the reviewed token edit, verifies non-execution on retest, checks literal text placement and preservation of an existing child, rolls back, then verifies execution returns. The fixture rejects dynamic/invalid positions, spreads, optional calls and mixed same-line operations. Source regression passed.
