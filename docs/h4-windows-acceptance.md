# قائمة قبول H4 الويندوزية — واجهات المواقع (Cap H)

> **من يُنفّذها:** خالدس، على جهازه، تفاعليًا. apiAnything يبقى **معطّلًا** حتى
> تجتاز هذه القائمة كاملة. كل صفحة سجّل نجاح/فشل + مقتطف من سجل Loam
> (بلا قيم كوكيز إطلاقًا).

## التجهيز قبل البدء (مرة واحدة)

1. `npm run vendor:api-anything` — يجلب الحزمة المثبّتة بالهاش (يلزم اتصال
   إنترنت مرة واحدة) ويتحقق أن `addons/api-anything/pkg/.vendored` يحمل
   الـcommit المعتمد `441e5090`.
2. `npm run check:api-anything` — يجب أن يطبع OK (الهاش مطابق).
3. فعّل الخدمة: في ملف `config.json` ضع `"apiAnything": { "enabled": true }`
   ثم أعد تشغيل Loam (سجّل أن إعادة التشغيل تمت).
4. افتح لوحة **الخدمات › واجهات المواقع** (بطاقة «واجهات المواقع» في شاشة
   الخدمات) وتأكد أن كتلة الحالة تظهر «جاهزة · متصل · 4 أدوات».
5. أنشئ مهمة بنمط automate وفعّل لها أدوات واجهات المواقع من زر
   «تفعيل أدوات واجهات المواقع لهذه المهمة» في اللوحة.

## القائمة W1–W15

| ID | الخطوة | المتوقع |
|---|---|---|
| W1 | كتلة الحالة تعرض Node | إصدار ≥ 22.13 |
| W2 | كتلة الحالة تعرض المتصفح | Microsoft Edge بمسار Program Files |
| W3 | «تسجيل الدخول» لموقع hacker-news | نافذة Edge تفتح **أمامك** خلال ١٠ ثوانٍ واللوحة تعرض «بانتظار إغلاق نافذة الدخول» |
| W4 | سجّل دخولك لHN ثم أغلق النافذة | اللوحة تعرض «مسجّل · N كوكيز» خلال ٥ ثوانٍ من الإغلاق؛ ابحث في `%APPDATA%\manus-local\logs\*` عن قيمة الكوكيز الظاهرة في DevTools — **يجب ألا توجد** |
| W5 | PowerShell: `icacls "$env:APPDATA\manus-local\api-anything"` | ACEs لخالدس وSYSTEM فقط؛ لا Users ولا Everyone ولا وراثة |
| W6 | في المهمة: «اسرد مواقع api-anything» | list_sites يعرض المواقع المرفقة (+ المتعلّمة) بلا أعداد كتابة |
| W7 | «ابحث في hacker news عن sqlite» | ok: true مع صفوف؛ بطاقة استئذان مرة واحدة |
| W8 | «اعرض مراجعات goodreads للكتاب 1» | نجاح، أو فشل auth/drift مع next يعيد توجيهه إلى api_heal (لا npx أبدًا) |
| W9 | «ابحث يوتيوب عن lofi» و«ابحث أمازون عن كابل usb-c» | ok، أو blocked مع محاولة tier 2 (لا توقف بلا محاولة) |
| W10 | تعلّم: api_capture على `https://news.ycombinator.com/newest` ثم api_add باسم hacker-news/newest | Edge يعمل headless (لا نافذة)؛ العملية تُحفظ وتظهر في العمليات |
| W11 | شغّل api_verify بالتوازي مع call_operation يحتاج تسجيلًا | كلاهما يكتمل (قد ينتظر أحدهما القفل ≤15 ث ثم ينجح)؛ ملف الجلسة يظل JSON سليمًا |
| W12 | ابدأ api_capture على صفحة بطيئة ثم اضغط إيقاف المهمة | خلال ٥ ثوانٍ لا msedge.exe يحمل api-anything في سطر الأوامر: `Get-CimInstance Win32_Process -Filter "name='msedge.exe'" \| ? CommandLine -match 'api-anything'` |
| W13 | أغلق Loam من الدوكة | لا عملية node تُبقي ملفات api-anything مفتوحة؛ الإقلاع التالي يعيد اتصال الخادم |
| W14 | الكتابة معطلة (الافتراضي): اطلب من الوكيل «انشر تعليقًا» عبر أي موقع | الوكيل يبلّغ عدم توفر عملية كتابة؛ لا نافذة ولا طلب؛ السجل بلا أي شيء لذلك الموقع |
| W15 | أثناء كل ما سبق: Defender/SmartScreen | لا مطالبة عند تشغيل msedge headless؛ إن ظهرت سجّلها |

## بعد الاجتياز

- سجّل النتائج في هذا الملف (عمود نتيجة لكل صف).
- عندها فقط يُترك `apiAnything.enabled: true` كوضع دائم.
- إن فشل أي صف: أرفق مقتطف السجل + رقم الصف، وأبقِ التفعيل معطّلًا.
