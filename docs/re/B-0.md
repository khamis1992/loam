# B-0 — App bridges recon

Resolves U-B1…U-B7 from BUILD_SPEC part B. Read-only; no spec contradictions found.

## U-B1 Approval API (WriteGate)
- `PendingKind` is a closed union (`src/server/pending.ts:7`); `WriteGate.stage(kind, summary, payload)` persists to `pending.json`.
- Tools stage only when `gate && gateActive()` (`src/server/settings.ts:83`; a missing `autoApprove` means approval is required). Pattern: `mutate` in `src/tools/skills.ts:357`.
- Approval executes in `applyPendingItem` (`src/server/http.ts:422`); the fallthrough calls `applySkill`, so a new kind needs its own branch **before** that line.
- Decision: route (a). Add `"app_run"` to `PendingKind`, plus an apply branch that calls `runBridge` from `src/bridges/exec.ts` and returns the redacted output.

## U-B2 Path confinement
- `resolveWrite(workspace, input?)` (`src/policy/paths.ts:43`) throws when the resolved path (including junction targets) leaves the workspace. Used for `cwd` and for every manifest arg typed `path` with a write effect.

## U-B3 Shell risk / vault helpers
- `shell_run` order: `checkCommandRisk` (Catastrophic blocks, Confirm refuses), `checkCommand(cfg, …)`, then `planVaultEnv` / `redactVaultValues`, with `vaultScope(ctx)`.
- Bridges never build a command string: argv arrays with `shell:false`. The joined argv is still passed through `checkCommandRisk` and `checkCommand` as a defense in depth.
- Timeout `min(cfg.policy.maxCommandSeconds, 900)`; capture cap `MAX_CAPTURE = 200_000`; cancel poll 300 ms using `isCancelled(taskId)` and `currentCancelEpoch()` from `src/server/runControl.js`; kill the tree with `taskkill /PID n /T /F`.

## U-B4 Skills
- `buildSkillFile(name, description, body, triggers[])` (`src/tools/skills.ts:235`). Directory: `SKILLS_DIR/<slug>/SKILL.md` (`src/config.ts:65`). Direct write is fine for generated bridge skills (not agent-authored, so no gate).

## U-B5 REST mounting
- `src/server/routes/<name>.ts` exports `handleXRoutes(req,res,p,url?,cfg?) → Promise<boolean>`, chained in `src/server/http.ts` near the other route handlers. Names must not clash with existing routes: use `src/server/routes/bridges.ts` and `/api/bridges`.

## U-B6 Computer-use fallback hints
- Real names: `computer_ui_tree`, `computer_ui_list`, `computer_ui_click`, `computer_ui_set_text` (`src/tools/computerUse.ts`). When no bridge fits, `app_run` returns a hint naming these; it never invokes them.

## U-B7 Windows install probes
- `where.exe <exe>`, then `%ProgramFiles%` / `%ProgramFiles(x86)%` / `%LOCALAPPDATA%\Programs` candidates from the manifest, then `reg.exe query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths\<exe>" /ve`. All via `execFile` with argv, short timeout.

## Wiring
- Tools: `src/setup/runtime.ts` (`registry.registerAll(createXTools(...))`, next to `createProjectWikiTools`). Gate object: `writeGate` is already in scope there.
- Modes: `src/modes/catalog.ts`. `app_list` and `app_describe` go in `CONTROL`; `app_run` goes in the main agent mode's tools list (it is gated, never auto-allowed).
- Config: `cfg.bridges?: { enabled?: Record<string, boolean> }`; default none enabled. The toggle is session-scoped (no config-persist helper), like the wiki.
