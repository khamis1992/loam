# بيانات فعلية في التطبيقات المولّدة — 2026-10-18

## ما أصبح يعمل

أُضيفت مجموعات بيانات ذات حقول نصية ورقمية وتاريخية ومنطقية وقوائم اختيار وعلاقات بين السجلات. التطبيق المولّد يعرض قوائم قابلة للبحث والتصفية، ونماذج إنشاء وتعديل، وحذفًا إلى المحذوفات مع استعادة. تمنع العلاقات حذف سجل ما زالت سجلات أخرى مرتبطة به. تظهر أخطاء الحقول دون استبدال البيانات المحفوظة، ويُرفض تحديث سجل تغيّر منذ فتحه.

يمكن إنشاء مخطط البيانات وتعديل تسمياته من «بيانات التطبيق» في الاستوديو. يدخل المخطط في حفظ المشروع والتراجع والإعادة، وتُحفظ سجلات المستخدم منفصلة عن تاريخ التصميم وعن الطلب المرسل إلى النموذج. التغيير الذي يحاول تبديل نوع حقل قائم أو وجهة علاقة أو إسقاط خيارات قائمة يرفض قبل الحفظ؛ مسار التوليد يعيده إلى محاولة التصحيح. إزالة عنصر القائمة ثم التراجع عن إزالته لا تمسح سجلاته.

المكوّن نفسه مضمّن في معاينة الويب والتصدير المستقل، وله تنفيذ Kotlin/Compose أصلي وتنفيذ React Native في مصدر Expo. حدود المخطط الحالية: 16 مجموعة، 16 حقلًا لكل مجموعة، و1000 سجل لكل مجموعة تشمل المحذوفات. لا يُزعم وجود مزامنة أو تخزين سحابي.

## التطبيق الذي اختُبر

أنشأ `qwen2.5:14b` محليًا «مساحة الإنجاز» من مشروع فارغ، ثم حُسّنت نصوصه. الطلب حدّد مجموعتي المشاريع والمهام وحقولهما ومعرّفاتهما؛ هذه تجربة توليد ذات متطلبات صريحة، وليست إثباتًا عامًا لفهم أي تطبيق من وصف حر. نجح التوليد في المحاولة الأولى. الأدلة: `release/mobile-live/records/local-generation.json` و`local-project.json`.

المشروع الحي: `task_mvdm1vnzcd14e405b6cf`، الإصدار 1، قسمان رئيسيان. سجل المهمة يتضمن الاسم والساعات والتاريخ والإنجاز والأولوية والارتباط بالمشروع. بيانات تجربة الويب منفصلة عن بيانات المحاكي؛ لم يُعدّل مشروع «رفيق الإنجاز» أو تُنقل بياناته.

## التحقق

- `npm run typecheck`: ناجح على شجرة العمل الحالية.
- `npm run check:mobile`: ناجح، بما فيه 40 صفحة، العزل وتعارض الإصدارات والحفظ والتنقل والرجوع، وإنشاء مجموعة من محرر البيانات ثم التراجع والإعادة مع بقاء سجلات المعاينة.
- `npm run check:mobile:records -- --project release/mobile-live/records/local-project.json`: ناجح على الناتج الفعلي للنموذج؛ إنشاء سجلين مستقلين، كل أنواع الحقول، تعديل وبحث وتصفية، منع حذف المرجع، حذف واستعادة، بقاء القيم بعد إعادة التحميل، نص المستخدم كبيانات حرفية، وعروض 320 و420 و768 دون تجاوز أفقي. يختبر أيضًا الحفظ داخل iframe دون `allow-forms`، وصياغة Expo ومصدر Android المصدّر.
- `npx tsx src/scripts/check-mobile-records-build.ts`: اختبار باستجابة نموذج مصطنعة يحاول تغيير نوع حقل؛ رفضها النظام وطلب تصحيحًا ثم حفظ المخطط المتوافق. لا يُحسب هذا كاستدعاء نموذج محلي حقيقي.
- اختبارات السجلات الافتراضية لها fixture محفوظ في المصدر؛ لا تحتاج ملفًا متولدًا في `release`. الخيار `--project` يختبر ناتج النموذج عند توفره.

## ما لم يُثبت بعد

المعاينة والتطبيق الأصلي يخزنان بياناتهما محليًا وبشكل مستقل؛ لا يوجد نقل بيانات بينهما أو حسابات أو مزامنة. لا تُحفظ مسودة النموذج غير المرسلة عبر كل عمليات التنقل. لا يوجد ضمان معاملات متزامنة بين تبويبات الويب، ولا اختبارات جهاز Android فعلي أو بناء Expo أو iOS. اختبار Android الحالي يستخدم قائمة واحدة في كل شاشة؛ العرض المتزامن لعدة قوائم وتحديث العلاقات بينهما يحتاج اختبارًا إضافيًا. مصدر النموذج ومحتواه ما زالا محكومين بالمخطط المتاح؛ الشروط والحسابات وقواعد العمل المتخصصة والتوليد متعدد المجالات مرحلة لاحقة. هذه النتيجة لا تثبت التفوق على Rork.
