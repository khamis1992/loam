# مراجعة الوصول إلى الخدمات وتكامل الواجهة

تاريخ المراجعة: 2026-10-18، بتوقيت الرياض.

هذا التقرير يوثّق الحالة قبل الإصلاح. راجع [إصلاحات 0.5.5 والتحقق](service-integration-fixes.md) للحالة اللاحقة؛ خصوصًا بوابة التكاملات والبحث والاختبارات، واستديو الجوال الذي أُضيف بعد المراجعة الأولى.

## الحكم

لا يمكن اعتبار جميع الخدمات متكاملة ومتاحة عبر الواجهة. هناك فرق بين النسخة العاملة والمصدر، وخدمات مسجلة لا تصل إليها مهام الواجهة، ومساحة جوال توضيحية. هذه مراجعة وليست تنفيذ إصلاحات. لم تُعدّل بيانات المستخدم أو يُعد تشغيل خادمه.

## النتائج حسب الأولوية

1. **النسخة العاملة قديمة وتفتقد الخدمات الجديدة.** أعاد `http://127.0.0.1:3939/api/identity` الإصدار 0.5.3، مقابل 0.5.4 في package.json. أعادت `/swarm.html` و`/security.html` و`/creative.js` و`/api/swarm/runs` الحالة 404. نجاح اختبارات المصدر لا يعني توفرها في التطبيق المفتوح. يلزم بناء الإصدار الحالي وتشغيله/تثبيته والتحقق من هويته ومساراته.
2. **اتصال MCP لا يساوي إتاحته للمحادثة.** الخادم العامل يعرض خمسة اتصالات ناجحة، ومنها loam-bridge مع 278 أداة. إجمالي الكتالوج 425 أداة، مقابل اتحاد 33 أداة متاحة ضمن الأنماط. هذا الفرق ليس عدد خدمات معطلة؛ بعض الأدوات داخلية أو لها مسار مستقل. لكن أدوات MCP كلها تحمل بادئة `mcp__` غير موجودة بقوائم الأنماط. يفرض `ToolRegistry.forMode()` تلك القوائم، وتستخدمها مهام المحادثة في src/index.ts. بالتالي لا يستطيع الوكيل استدعاء هذه التكاملات من المحادثة المعتادة رغم ظهور حالة اتصالها. المراجع: src/tools/mcp.ts:99، src/tools/registry.ts:40، src/modes/catalog.ts، src/index.ts.
3. **استديو الجوال ليس استديو تنفيذ متكاملًا.** المسار `/#/studios/mobile` يفتح ui/studios/index.html. يصرح integration.js بأن البيانات أمثلة تصميمية؛ إرسال الطلب يحوّله إلى نمط build. أدوات `rork_build` و`rork_from_web` مسجلة في runtime لكنها غير مدرجة ضمن أدوات build. بناء مشروع عام ممكن، أما المحاكي والتدفقات والمشاركة المتخصصة فلا يثبتها هذا الربط. المراجع: ui/app.js:247، ui/studios/integration.js، src/tools/rork.ts:139، src/setup/runtime.ts:72.
4. **جسر القدرات المتخصصة غير موصول كخدمات مستقلة.** مسارات Frontier وMiroFish موجودة في الخادم، وأدوات مثل super_swarm وlovable_studio وmirofish_chat مسجلة، لكن لا توجد استدعاءات لمساراتها في ملفات الواجهة الحالية ولا سماح لها ضمن الأنماط. لا يشمل هذا الحكم خدمة الأسراب الجديدة `/api/swarm/runs`؛ لها واجهة مستقلة واجتازت اختبارها.
5. **البحث يقرأ الروابط دون محرك بحث مدمج.** README يصف بحث الويب، لكن src/tools/web.ts يعرّف web_fetch فقط، ونمط research يسمح بقراءة الروابط دون web_search. يلزم ضبط الوصف أو إضافة البحث الفعلي وربطه.
6. **الاختبار العام للواجهة غير مواكب للاستديوهات الجديدة.** فشل check:loam-ui عند انتظار `#studioPrepare` داخل صفحة الأسراب، ويعاملها كتدفق research القديم. صفحة الأسراب الحالية تستخدم نموذجًا خاصًا، واختبارها المستقل نجح. لذلك هذا الفشل لا يثبت عطل صفحة الأسراب، لكنه يمنع اعتبار حزمة التحقق العامة ناجحة. المرجع: src/scripts/check-loam-ui.mjs:80 و86.

## تغطية الخدمات

| المجموعة | الوصول من الواجهة في المصدر | التحقق في هذه المراجعة |
| --- | --- | --- |
| الأنماط السبعة والمهام والمرفقات والملفات | الرئيسية وصفحات الأنماط والمهام | فحص المصدر؛ الاختبار العام توقف عند استديو الأسراب |
| المشاريع والمواعيد | الشريط الجانبي؛ إنشاء وحذف وبدء مهمة مشروع | ربط الواجهة بمسارات الخادم موجود؛ لم يُختبر تشغيل موعد فعلي |
| الأوفيس | استديو الأوفيس/اكتب/حلّل | نجح HTTP الفعلي: تحرير وحفظ وتصدير DOCX/PPTX/XLSX وعزل واستمرارية؛ نجح اختبار واجهة الاستيراد ببيانات محاكاة |
| التصميم ثلاثي الأبعاد | صمّم/استديو الإبداع | نجح HTTP وEdge وWebGL والحفظ وإعادة الفتح؛ نجح اختبار التصدير PNG/GLB والتحرير والعزل |
| الأسراب الجديدة | بطاقة الاستديو | نجح نموذج الواجهة وستة أدوار وكتابة ملفات وتشغيل اختبارات وتنزيل وإلغاء وإعادة محاولة؛ النموذج اللغوي محاكاة بروتوكول |
| الأمن | بطاقة استديو الأمن | نجح تشغيل من الواجهة وتقدم وأدلة وتصدير وعزل واستمرارية على هدف اختبار محلي |
| المهارات والذاكرة والمعرفة والتقييم والمساعدون | صفحة الخدمات وروابط جانبية | ربط المصدر موجود؛ الاختبار الفرعي يغطي المساعدين والمرفقات والشاشة والطرفية، ولا يثبت كل عملية في هذه الصفحات |
| الشاشة | الخدمات ← الشاشة | تحقق عدم الاشتراك التلقائي؛ لم تُلتقط شاشة المستخدم |
| الطرفية | مهمة من نمط build | رابط بمعرف المهمة؛ تحقق منع الإنشاء دون مهمة، ولم يُنفذ أمر في بيانات المستخدم |
| النماذج | محدد جانبي وصفحة الخدمات | الخادم العامل أعاد 30 نموذجًا؛ لم يُختبر الاستدلال لكل نموذج |
| MCP | حالة اتصال في صفحة الخدمات | اتصالات حية ناجحة، لكن أدواتها غير متاحة ضمن قوائم أدوات المحادثة |
| التحديثات | قائمة Electron | مسار واجهة موجود؛ لم يُختبر تثبيت تحديث |
| إعداد workspace وhooks | API في الخادم | لا توجد استدعاءات UI مباشرة لمسارات الإعداد هذه؛ يلزم تحديد إن كانت إعدادات متقدمة مطلوبة للمستخدم |

استُثنيت خدمات الطابور والحفظ وSQLite والاستعادة والتضمين والسجلات والخطافات الداخلية من اشتراط صفحة مستقلة. لا تحتاج كل أداة منخفضة المستوى إلى زر؛ المطلوب أن توجد رحلة استخدام حقيقية للقدرة المعلنة.

## الاختبارات المنفذة

- ناجح: `npm run typecheck` في الفحص النهائي. ظهر خطأ Word أولًا ثم اختفى في إعادة الفحص بعد تغير المصدر أثناء المراجعة؛ لم أصلحه ضمن هذه المراجعة.
- ناجح: `npm run check:loam-ancillary`.
- ناجح: `npm run check:studio-http`.
- ناجح: `npm run check:studio-import-ui`.
- ناجح: `npm run check:swarm-ui`.
- ناجح: `npx tsx src/scripts/check-security-http.ts`.
- ناجح: `npm run check:creative-http`.
- ناجح: `npm run check:creative-ui`.
- غير ناجح: `npm run check:loam-ui` بسبب توقع عنصر قديم في صفحة الأسراب.

كانت الشجرة تحتوي على تعديلات سابقة وتغيرت أثناء المراجعة؛ النتائج لقطة من المصدر الذي اختُبر وليست اعتمادًا لحزمة إصدار ثابتة. اختبارات الخدمات استخدمت خوادم وبيانات اختبار معزولة. فحوص الخادم العامل اقتصرت على القراءة. لا تمثل هذه النتائج اختبار جودة النماذج الحية أو جميع التكاملات الخارجية.
